# examples/locomotion

## Intent
RL locomotion stack for the Unitree Go2 in Genesis: a scripted-trot demo whose control and reward math run as compiled EvoX Compiler (`evoxc`) graphs, a TensorNEAT neuroevolution trainer for walking on the same graph layer, an rsl-rl PPO stack and pre-trained backflip playback.
The TensorNEAT stack (`go2_neat_kernels.py`, `go2_device_kernels.py`, `go2_neat_env.py`, `go2_device_rollout.py`, `go2_neat_train.py`) sits on `../neuroevolution/` and is reproducible from zero with the pinned baseline, commands and measured numbers below.
Its GPU path is Torch-free and fully device-resident: `--torch-free` runs population init, rollout, fitness and `tell()` with no `torch` in the process, on one backend/device (`iree@rocm:0` on the MI300X host), while `residency="numpy"` stays the default host-staged reference.
`residency="device"` without the flag is the same zero-copy loop in a Torch-present process, where the torch setters and a bool error mask are allowed.

## API Surface

### Scripted trot on EvoX Compiler graphs
- `try1.py` → demo: viewer until closed (under pytest: no viewer, 5 steps), `--max-steps N`, `--headless` = 250 steps writing `go2_reward.png` next to the script; `--evox-backend`/`--evox-device` select the graph backend/device (default `numpy`/`cpu:0`).
- `go2_evox_kernels.py` → the two `evoxc` graphs (no torch, no genesis), compiled once and reused every step: `GAIT` (runtime `step` 0-d int32 + `previous_action` → `targets`/`action`/`action_change`) and `REWARD` (runtime `base_pos`, `base_quat`, `base_lin_vel_world`, `base_ang_vel_world`, `dof_pos`, `action_change` → the six Go2 Walking terms + `total`), with the standing pose, `phases` (`[0, pi, pi, 0]` per leg), `dt` and `1/action_scale` as statics.
  Helpers `DT`, `ACTION_SCALE`, `STANDING`/`STANDING_FLAT`, `REWARD_TERM_NAMES`, `resolve_backend_device`, `build_gait`/`run_gait`, `build_reward`/`run_reward`, `_constant`/`_to_device_array`/`_to_numpy`; `go2_legacy_reference.py` keeps the pre-migration math (`gait_step`, `walking_reward_terms`) as the parity oracle.

### TensorNEAT Go2 walking graphs (`go2_neat_kernels.py`)
- Pure-`evoxc` module (no genesis, no simulation): `build_obs`/`run_obs`, `build_advance`/`run_advance`, the `go2_env` task constants, and the tile helpers the device rollout reuses (`_tile_standing`, `_tile_commands`, `_tile_scaled_commands`).
- It imports the task math from `go2_evox_kernels.py` and the task-agnostic half from `../neuroevolution/` (`build_policy`/`run_policy`, the fitness and tell builders plus `ExecutableCache`, `EPISODES_PER_POLICY`/`Perturbation`, `_attach`/`_device_name`/`_outputs`/`_positive_int`/`_rows_of`/`_staged`); no graph or helper logic is duplicated.
- `_ensure_shared_layer_path()` is the stack's only `sys.path` shim: it runs at import time and puts `<repo>/examples/neuroevolution` on `sys.path`, so every module here imports `go2_neat_kernels` first and the shared layer by bare name afterwards.
- Constants: `NUM_OBS=45`, `NUM_ACTIONS=12`, `CLIP_ACTIONS=100.0`, `TERMINATION_LIMIT_DEG=10.0`, `OBS_SCALES`, `REWARD_SCALES`, `TRACKING_SIGMA=0.25`, `BASE_HEIGHT_TARGET=0.3`, `DEFAULT_COMMANDS`; the last five are `go2_env`'s `obs_cfg`/`reward_cfg` restated here, and `DEFAULT_COMMANDS = [0.5, 0, 0]` is exact because `go2_train.get_cfgs()` uses singleton ranges.
- `build_policy(algo, config, pop_arrays, rows, *, backend, device)` is a one-line adapter binding `num_inputs=NUM_OBS`/`num_outputs=NUM_ACTIONS`; `run_policy`, the fitness/tell builders and `ExecutableCache` are re-exported unchanged (fitness = per-policy episode mean, `tell()` → `{"randkey","generation","pop","species"}`).
- `run_obs` → `(rows,45)` (as `go2_env._update_observation`); `run_advance` → `{"obs","reward","returns","alive","done","episode_length"}` with ±100 clipping, the six dt-scaled reward terms, `alive`/`done`/`returns` masking, an int32 episode counter and arctan2-free roll/pitch termination.

### Device-only graphs (`go2_device_kernels.py`)
- Pure `numpy` + `evoxc` module (no genesis, no torch, no simulation): the three graphs that exist so no per-step value of the device rollout leaves the GPU, each compiled once and reused across steps and generations.
- `build_control(rows, *, action_scale, actions_dof_idx, clip_actions, backend="numpy", device=None)` / `run_control(executable, *, raw_actions, done, permutation=None, default_targets, clip_actions=None)` → `(targets, last_actions)`, both `(rows,12)` float32: `clipped = min(max(raw,-clip),clip)`, `last_actions = clipped*(1-done)` (the numpy path's `last_actions[reset_idx] = 0.0`), `targets = matmul(last_actions, permutation)*action_scale + default_targets`.
  `targets` goes to `control_dofs_position(targets, slice(dof_low, dof_high))`; `last_actions` is in action order (the observation's `actions` slot and the `action_rate` reference).
- `build_state(rows, *, num_dof, qpos_dof_slot, mask_is_bool=False, backend, device)` / `run_state(executable, *, base_quat_world, dof_pos_block, dof_vel_block, inv_init_quat, error_mask, gather=None)` → `(base_quat, dof_pos, dof_vel, error_flag)`: transposes the batch-last `(12, rows)` dof blocks, gathers them into action order with `permutation_matrix(qpos_dof_slot, 12)`, composes `normalize(quat_mul(base_quat_world, inv_init_quat))` in-graph in the `go2_neat_env._quat_mul` coefficient form, and derives `error_flag = not_equal(error_mask, 0)`; `mask_is_bool` is static and fixes that input's dtype (bool with Torch, int32 `DeviceView` without) because one compiled graph cannot accept both.
- `build_episode_returns(n_policies, *, episodes_per_policy=EPISODES_PER_POLICY, backend, device)` / `run_episode_returns(executable, returns)` → the `(pop_size, episodes)` matrix as a compiled `evoxc.reshape`, the only way to reshape a device buffer without a host copy.
- Helpers: `permutation_matrix(order, width)` = the `(width, width)` float32 matrix with `P[order[k], k] = 1`, so `matmul(x, P)` is `x[:, order]`; `default_targets_tile(rows, default_dof_pos, actions_dof_idx)` = the `(rows,12)` default-pose tile in the actuator slice's dof order; `_operand` stages a NumPy operand and passes an `evoxc` tensor through; `NUM_MOTORS = NUM_ACTIONS`.
- Each `build_*` stashes its static half on the executable (`.permutation`, `.gather`, `.rows`, `.action_scale`, `.clip_actions`, `.mask_is_bool`, `.n_policies`, `.episodes_per_policy`, `.num_dof`, `.qpos_dof_slot`, `.actions_dof_idx`, `.graph`, `.device_name`), and `run_*` re-passes it per call because a static ndarray cannot enter `evoxc.matmul` and `evoxc.constant` only works inside a trace.
- The control graph runs at the END of a step: the rollout writes its `targets` on the following iteration, which reproduces `simulate_action_latency` (step `t` executes the action computed from `obs_{t-1}`, step 0 executes the default pose).

### TensorNEAT Go2 walking trainer (`go2_neat_env.py` + `go2_neat_train.py`)
- `go2_neat_env.py` is the batched, seeded evaluation env (no CLI); `go2_neat_train.py` is the CLI entry that drives NEAT generations through it.
- `Go2NeatEnv` builds ONE `gs.Scene` with `n_envs = rows = EPISODES_PER_POLICY * pop_size` (policy `p` owns rows `3p, 3p+1, 3p+2`), the same plane+Go2 morphs, `SimOptions(dt=0.02, substeps=2)` and `RigidOptions(enable_self_collision=False, max_collision_pairs=20, tolerance=1e-5, batch_dofs_info=not HAS_TORCH)` as `go2_env.py`; `CFG` is a literal copy of `go2_train.get_cfgs()` because that module cannot be imported without `rsl-rl-lib`.
- Public API: `generation_seed_table(master_seed, num_generations, episodes=EPISODES_PER_POLICY) -> (G,3) int64`, `evolution_seed(master_seed) -> int`, `perturbation_from_seed(...)`, `perturbed_init_qpos(...) -> (3,19)`, plus `Perturbation`/`EPISODES_PER_POLICY` re-exported from `../neuroevolution/seeding.py`; the class is `Go2NeatEnv(BatchedEpisodeEnv, pop_size, master_seed, *, perturbation=Perturbation(), horizon=None, episode_length_s=None, backend="numpy", device=None, show_viewer=False, seed_table=None, stop_when_done=True, residency="numpy")`.
- `residency` selects where graph-boundary values live: `"numpy"` (reference: `read_state` → host arrays → `run_*`) or `"device"` (zero-copy operands via `go2_device_rollout.py`); a `"device"` request on a cpu-kind `evoxc` device raises `ValueError` in `__init__` and never falls back to host staging.
- Both modes return the same result mapping; `evaluate` validates with `env_base.validate_evaluation_device(result, pop_size, episodes_per_policy, device)` under device residency (tensor metadata only, returns tiling and fitness rule verified in-graph) and `env_base.validate_evaluation(...)` otherwise.
- `executables()` returns `(obs, policy, advance, fitness)` under `residency="numpy"` and the 7-tuple `(obs, policy, advance, fitness, control, state, episode_returns)` under `residency="device"`, each entry a `self.cache` lookup; the device graphs use `("control", rows, action_scale, CLIP_ACTIONS, backend, device_name)`, `("state", rows, NUM_ACTIONS, mask_is_bool, backend, device_name)` and `("episode_returns", pop_size, 3, backend, device_name)`, so every generation after `__init__` is a cache hit.
- `_error_mask_is_bool()` derives the `mask_is_bool` static from the dtype of the scene's own `get_error_envs_mask()`; `_build_policy_trace()` uses the shared `trainer.TraceOnlyProblem(45, 12)` and `trainer.pop_arrays_of(state)`.
- `evaluate(pop_arrays, generation)` returns `seeds`, `episode_returns` `(NP,3)`, `returns` `(rows,)`, `fitness` `(NP,)` float32, `steps`, `env_steps`, `wall_time_s`, `steps_per_s`, `env_steps_per_s`, `cache_hits`, `cache_misses`, `end_reasons` and `init_qpos`; `env_steps = steps * rows`, and under device residency only the four training leaves are device tensors.
- `_evaluate_numpy()`, `read_state()`, `_write_targets()`, `_write_reset()` and `_reset_generation()` are the numpy path and stay the reference; `_classify_endings()` classifies a row once, on its first ending.
  Its relative base quaternion is a host NumPy `_quat_mul` transcription of `_tc_quat_mul`'s coefficient form (`_QUAT_MUL_COEFFICIENTS` must equal `_tc_geom_constants().quat_mul`) because numba's `transform_quat_by_quat` drifts from the torch reference (2.1e-4 on a fitness over 21 steps), and it still pays every device hop (132.7–146.9 steps/s on the MI300X vs 172.1–176.0 on CPU).
- `horizon` = `scene.step()` calls per generation, default `max_episode_length` (`episode_length_s / dt` = 1000) and baked into `build_advance`; `stop_when_done=True` ends a generation once every row's `alive` is False.
- `end_reasons` uses `END_REASONS = {"unfinished": 0, "timeout": 1, "tilted": 2, "error": 3}`: `error` = the genesis error-mask flag, `tilted` = roll/pitch beyond `termination_if_*_greater_than` in the `quat_to_xyz` convention, `timeout` = any other `done`, `unfinished` = still alive when the horizon or early stop ended the generation.
- CLI: `--pop-size` (8), `--generations` (2; 1 under pytest), `--horizon` (full; 20 under pytest), `--episode-length-s` (20.0), `--master-seed` (0), the three `--perturb-*` amplitudes (0.05) plus `--no-perturbation`, `--stop-when-done`/`--no-stop-when-done`, `-e/--exp-name`, `-o/--output-dir` (`out/go2_neat`), `-g/--gpu`, `--evoxc-backend`/`--evoxc-device`, `--tell-backend {numpy,iree,xla}` (inherits the rollout backend except on ROCm, where it defaults to `xla`), `--pjrt-plugin`, `--residency {numpy,device}`, `--torch-free`, `-v/--vis`, `--quiet`; `GS_HSA_REEXEC=0` disables the ROCm HSA repair.
- `--torch-free` is the device residency with the Torch claim enforced: it implies `--residency device`, defaults the rollout to `iree` on `rocm:0` (a CUDA host passes `--evoxc-device cuda:0`), inits GPU Genesis with `performance_mode=False`, and refuses `-v/--vis`, `--evoxc-backend numpy`, `--tell-backend xla`, `--tell-backend numpy` and `--pjrt-plugin` because device residency is single-backend, so evolution runs on the env's own `iree@<device>` (`tell_backend=None`, `plugin_path=None` forwarded).
  It raises as soon as `torch` reaches the process — after the scene build and after the evolution-graph build — and warns once more before exit.
- The header and the `done: ...` line print `torch_free=<bool> torch_in_process=<bool>`; `summary.json` merges `residency`, `torch_free`, `torch_in_process`, `genesis_backend` (`"gpu"` with `-g` or `--torch-free`, else `"cpu"`), `horizon`, `episode_length_s`, `perturbation`, `evoxc_backend`, `evoxc_device`, `show_viewer` and `stop_when_done` into `config`.
- The trainer owns the ask/tell loop (`DefaultGenome(45, 12, max_nodes=80, max_conns=640)`, `NEAT`, `Pipeline(seed=evolution_seed(master_seed))`, then per generation ask → `env.evaluate` → fitness aggregation → `run_tell`); under device residency it also initializes the population, RNG key, generation counter and species leaves on `env.device` (`device_runtime.device_setup`), then applies and verifies the fitness rule in-graph.
- `go2_neat_train.py` is CLI + wiring + artifacts: it passes one `seed_table=generation_seed_table(master_seed, generations)` to both env and trainer, calls `trainer.setup()` + `trainer.run()`, and writes `history.jsonl` plus `summary.json` under `--output-dir` (both git-ignored); `go2_train.py` stays the untouched PPO path.
- Env graphs are built once in `__init__` (four, or seven under device residency) and the tell, fitness-rule and verification graphs once in `trainer.setup()`, all through one `ExecutableCache`; `setup()` logs `Setup done in ... s (device residency, tell ..., rule ..., verification ..., cache H hits / M misses)` and each generation then logs `cache +3/+0`.

### Device-resident rollout (`go2_device_rollout.py`)
- Public entry: `evaluate_device(env, *, executables, pop_arrays, seeds, init_qpos, row_init_qpos, horizon, stop_when_done)`; `Go2NeatEnv.evaluate` imports it lazily, so the numpy path never loads an IREE runtime.
- It imports no Torch: quadrants (`qd.sync()`), `genesis.utils.device_buffer.DeviceView`, `genesis.utils.geom.inv_quat`/`quat_to_xyz`, `genesis.utils.torch_compat.HAS_TORCH` (a flag only), the three device graphs and the Go2 constants.
- The executables tuple is 7 (`obs, policy, advance, fitness, control, state, episode_returns`), every entry must live on one device, and the Go2 must have `robot.n_qs == 7 + 12`.
- `_DeviceRollout` serves one generation: cached `DeviceView` slices of `solver.dyn_state.dofs.pos`/`.vel` (keyed by field id), the HAL device discovered from the first device payload, the per-generation staged tiles and the host init-qpos tile a mid-loop reset needs.
- `_operand(value)` is the Quadrants → IREE bridge: `self._hal.from_dlpack_capsule(view.__dlpack__())` wraps the same memory as an IREE HAL buffer view and `evoxc.core.Tensor(IreeDevicePayload(rt.DeviceArray(hal, view), device))` is the operand (the call form of `evoxc.backends.adapters.iree._device_array_from_dlpack`); `_live()` compacts a strided getter with `.contiguous()` on the device, `_stage(array)` is the only host → device copy and `_host(tensor)` is `payload.to_host()`.
- The loop mirrors `_evaluate_numpy`: policy on the previous observation → write the PREVIOUS step's `targets` (`control_dofs_position`) → `scene.step()` → `qd.sync()` → state graph → advance graph → control graph (next `targets` and `last_actions`, rows that just ended zeroed) → read `done`.
  When a row ended: one readback of `base_quat` and `error_flag`, `env._classify_endings` (the rule keeps one owner), `_reset_rows`, `scene.clear_errno()` if any flag is set, then `qd.sync()` again.
- `_sync()` runs at most twice per step (after `scene.step()`, after a reset write) plus once per generation for the initial reset; nothing else needs a fence because `IreeExecutable.run` blocks on its own queue, and a reset observation comes from the observation graph on the known reset values (zero base angular velocity, identity orientation relative to the init pose, the init joint positions and zero velocities/actions), so it costs no simulation step.
- `_reset_rows` adapts the two `set_qpos` contracts: the torch-free staged setter takes the whole `(rows, 19)` tile plus `envs_idx` (already on the device), while the torch setter scatters only the selected rows, so `HAS_TORCH` picks the form.

Per-boundary data flow of one device-resident step:

| boundary | backend | device | copy |
| --- | --- | --- | --- |
| solver `dofs.pos/.vel` slice `[dof_low:dof_high]` → state graph | Quadrants → IREE | rocm:0 | DLPack, none (contiguous batch-last view) |
| `get_pos`/`get_quat`/`get_vel`/`get_ang`, error mask → graphs | Quadrants → IREE | rocm:0 | DLPack, none |
| obs → policy → action → control → PD targets → `control_dofs_position` | IREE → Quadrants | rocm:0 | device→device `hipMemcpy2DAsync` |
| advance outputs → next graph (obs, returns, alive, episode_length) | IREE | rocm:0 | none (same payload) |
| `episode_returns` | IREE graph | rocm:0 | none (never `DeviceArray.reshape`) |
| per-generation metadata: `(rows,19)` init-qpos tile, `inv_init_quat`, default-target/zero/identity tiles, seeds | host → device | — | one staging batch per generation |
| `done` per step, `base_quat`/`error_flag` on ending steps | host readback | — | rows bytes / a few hundred bytes |
| pop leaves → policy; tell operands; next-generation population | IREE | rocm:0 | none (trainer keeps them resident) |

- One exception inside that table: `run_control`/`run_state` are called without `permutation=`/`gather=`, so `_operand` stages the executables' host NumPy `(12,12)` defaults on every call (576 B each), i.e. a per-step H2D.

Remaining host touches, exhaustive: per step the `done` mask (`rows` bools → `np.flatnonzero`, the `end_reasons` classification and the host `alive` mirror that `stop_when_done` checks, since `alive` never re-arms); on an ending step the `base_quat` rows (classification through `quat_to_xyz(..., rpy=True, degrees=True)`) and the `error_flag` vector, read only there because a flagged row is always a `done` row; per generation the staging batch above, the returned `init_qpos` and the host metrics (`steps`, `env_steps`, `wall_time_s`, the three rate fields, both cache counters, `end_reasons`).
The termination decision itself is computed in-graph by `run_advance`; the host only reads the resulting `done` mask.

### Seed rules
- `np.random.SeedSequence(master_seed).spawn(2)` gives `(evolution_seq, env_seq)`: `evolution_seed(master_seed)` is the first child (`evolution_seed(0) = 3757552657`, feeding `Pipeline(seed=...)`) and the second drives `generation_seed_table`, so the streams are independent.
- One table row per generation with 3 distinct seeds, shared by every policy and by all three rows of a policy, so all policies face identical reset perturbations.
- `perturbation_from_seed` draws the whole reset (base position offset, a small w-first `base_quat` rotation, 12 joint offsets, each component uniform in `[-p, p]`) from `default_rng(seed)` alone, and returns exact zeros when `Perturbation.is_zero`.
- `perturbed_init_qpos` composes `q_pert * q_init` (`R_pert @ R_init`), i.e. the sampled `base_rpy` rotation acts in world axes after the authored init orientation; the body-axis order is a real difference for a non-identity init quaternion, and the Go2 `base_init_quat = [1,0,0,0]` makes both agree bit-for-bit here.
- A perturbed episode keeps its perturbation across auto-reset (post-reset episodes are discarded by the `alive`/`returns` masking); fitness = mean of the policy's 3 episode returns, and an episode return includes the step that ended it.

### RL stack
- `go2_env.py` → `Go2Env`: vectorized (`num_envs`) Go2 environment using `tensordict.TensorDict`; 50 Hz control (`dt=0.02`, `substeps=2`) over 12 motors via PD position control; one 45-dim `"policy"` observation (3 base ang-vel + 3 projected gravity + 3 commands + 12 dof-pos + 12 dof-vel + 12 actions); rewards auto-discovered via `_reward_<name>`.
- `go2_train.py` → PPO via `rsl_rl.runners.OnPolicyRunner` (4096 GPU envs, `logs/<exp_name>/`); `go2_eval.py` loads a checkpoint into a single CPU viewer env; `go2_backflip.py` defines `BackflipEnv(Go2Env)` (60-dim phase-augmented observation) and plays `single.pt`/`double.pt` from `backflip/`.

## Run commands
Run from the repo root; the script's directory lands on `sys.path`, so `go2_neat_env`/`go2_neat_kernels` import by bare module name.
- Smoke, NP=8, 2 × horizon 25 (numpy residency): `python examples/locomotion/go2_neat_train.py --pop-size 8 --generations 2 --horizon 25 --output-dir out/neat_smoke` → best −7.3785 / −7.3180, 21 then 10 steps.
- Zero perturbation: `--generations 2 --horizon 25 --no-perturbation` → best −7.4132 / −7.4132; reproduction check = run twice with the same `--master-seed 0` into two `--output-dir`s and compare `history.jsonl`.
- Timeout probe: `--pop-size 8 --generations 1 --episode-length-s 0.1 --horizon 40` (`max_episode_length=5`) → `timeout=12 tilted=12`.
- Torch-free smoke: `python examples/locomotion/go2_neat_train.py --torch-free --pop-size 8 --generations 2 --horizon 25 --output-dir out/neat_tf_smoke` → best −7.3785 / −7.3180, 21 then 10 steps, `cache +3/+0`; full horizon = the same with `--generations 3 --no-stop-when-done`; pop 32 and the timeout probe = the same flags with `--pop-size 32` / `--generations 1 --episode-length-s 0.1 --horizon 40`.
- Torch-free on CUDA: add `--evoxc-device cuda:0` (`--torch-free` otherwise defaults to `rocm:0`); that configuration is unmeasured.
- Torch-blocking probe: prepend a directory holding a `torch/__init__.py` that raises `ImportError` (`PYTHONPATH=/tmp/notorch:$PWD python examples/locomotion/go2_neat_train.py --torch-free ...`); the run must still finish and report `torch_in_process=False`.
- Device residency without the torch claim: `--residency device` on a non-CPU device, e.g. `-g --evoxc-backend iree --evoxc-device rocm:0 --tell-backend numpy --residency device --pop-size 8 --generations 2 --horizon 25`; a cpu-kind device is rejected up front with `ValueError`.
- ROCm numpy residency, verified 3000-step command: `-g --evoxc-backend iree --evoxc-device rocm:0 --tell-backend numpy --pop-size 8 --generations 3 --horizon 1000 --no-stop-when-done`; add `--pjrt-plugin` and drop `--tell-backend numpy` for XLA evolution, or set `--evoxc-backend xla` to run rollout and evolution both on XLA/`rocm:0`.
  That residency needs `--tell-backend numpy` or a PJRT plugin because its `tell()` defaults to `xla`, and without one it fails with `BackendError: the xla adapter requires a PJRT C API plugin library`.
- Every run writes `<output-dir>/history.jsonl` and `summary.json`; the per-generation stdout line carries `seeds [...]`, best fitness, steps and `ends ...`.

## Measured numbers (TensorNEAT trainer, numpy residency)
- Compile cost: the 5 executables cost 8.3–10.3 s warm and 36.7 s on a cold first run; afterwards every generation logs `cache +1/+0`.
- NP=8 (24 rows), 1000 steps, `--no-stop-when-done`: 5.810 / 5.768 / 5.682 s per generation (172.1 / 173.4 / 176.0 steps/s, 4131 / 4161 / 4224 env-steps/s), best −7.3785 / −7.3180 / −6.0399, tilted=24 and timeout=0 each; 3000 steps in 17.3 s.

## Torch boundary
The Torch-free path has no torch at all in the process: population init, the seven rollout graphs, the fitness rule, the verification and `tell()` run where `"torch" not in sys.modules` after a full 3 × 1000-step run, which `--torch-free` asserts after the scene build, after the evolution-graph build and once more before exit (reported as `torch_in_process`).
- `gs.init`/`gs.Scene.build` run on a torch-optional Genesis build; the getters hand back `DeviceView` zero-copy views and the setters accept DLPack producers device to device.
- `go2_neat_env.py`, `go2_device_kernels.py`, `go2_device_rollout.py` and `go2_neat_train.py` contain no `import torch` and no torch operation; the rollout imports `HAS_TORCH` only as a flag.
- AST scan (no `import torch`/`from torch ...`): `python -c "import ast,sys;[print(p,[n.names[0].name for n in ast.walk(ast.parse(open(p).read())) if isinstance(n,ast.Import) and 'torch' in n.names[0].name]) for p in sys.argv[1:]]"` over those four modules.

## Constraints
- Scripts are plain modules, not a package; run from the repo root, and `try1.py` imports `go2_evox_kernels` by bare module name; both need `evoxc`, which is NOT declared in `pyproject.toml`, and control/reward math lives exclusively in `go2_evox_kernels.py` (never re-derived in `try1.py`).
- `go2_neat_kernels.py` is deliberately one module (~660 lines): the single import surface the env/train/device modules build against, and the owner of the stack's only `sys.path` shim, so do not split it; its re-exports (`build_policy` adapter, the fitness/tell builders, `ExecutableCache`, `EPISODES_PER_POLICY`/`Perturbation`, and `perturbation_from_seed` in `go2_neat_env.py`) keep the tests and `../drone` importing unchanged, each a one-line delegation that may not grow logic.
- The compiled graphs are shared by both residencies, so neither their dtypes/signatures nor the compute may be specialized for the device bridge; the one allowed dtype switch is the state graph's `mask_is_bool`.
- Device residency needs a non-CPU `evoxc` device backed by IREE (`iree` on `rocm:0`/`cuda:0`); a `numpy`/`cpu:0` configuration is rejected at construction, and the numpy path never imports an IREE runtime.
- `--torch-free` is single-backend and GPU-only: no viewer, no numpy rollout backend, no `--tell-backend`, no `--pjrt-plugin`, and it raises as soon as `torch` reaches the process.
- `go2_train.py`/`go2_eval.py` enforce `rsl-rl-lib>=5.0.0` via `importlib.metadata` at import time; `go2_env.py` needs `tensordict.TensorDict`; `go2_reward.png` is a git-ignored artifact next to `try1.py`.

## Design Decisions
- Static graph specializations (standing pose, phases, dt, 1/action_scale, thresholds, max_episode_length, tiled commands) keep the runtime signature to genuinely per-step values, and every `run_*` re-passes them per call.
- `SimOptions(dt=0.02, substeps=2)` matches the robot's 50 Hz control rate; `simulate_action_latency=True` executes the previous step's action, which the device residency reproduces by running the control graph at the end of the step.
- `RigidOptions(enable_self_collision=False, max_collision_pairs=20, tolerance=1e-5)` is tuned for a policy with few contact pairs.
- `batch_dofs_info=not HAS_TORCH` is gated on torch presence because the torch-free dofs-info kernel rejects `envs_idx=None`; the values written are identical, and `performance_mode` is off for the torch-free run only because its staged ndarray state is not consumable by the torch-free setters.
- One scene with `3 * pop_size` rows (not 3 sequential episodes per policy) keeps every policy on identical reset perturbations and amortizes one `scene.step()` across all rows.
- Three small device graphs rather than host code: a device operand must not be reshaped, permuted or composed on the host, and any host roundtrip is exactly what the residency removes.
- Device residency is single-backend by construction (a foreign payload cannot enter the rollout executables), so evolution must run on the same backend/device and `--torch-free` forwards `tell_backend=None`.
- `tell()` selection and its ROCm workarounds are device-gated: ROCm defaults to `xla` (IREE cannot compile that graph there) and gets the teardown `os._exit(0)`, CUDA keeps `iree` plus the reduction-distribution flag, CPU keeps `numpy`, and an explicit `--tell-backend` wins; `--pjrt-plugin` forwards a `plugin_path` compile option and fills `EVOXC_PJRT_PLUGIN` only when unset.
- The HSA-runtime repair is owned by `gs.init` (`genesis/utils/hsa.py`), not by this stack: `LD_PRELOAD` must exist before the loader maps torch's HIP/HSA libraries, so it re-execs the process; `GS_HSA_REEXEC=0` opts out and `GS_HSA_REEXEC_DONE=1` is its sentinel.

## Dependencies
- `evoxc` 0.1.0 (VCS, not declared) plus the optional `iree-base-compiler`/`iree-base-runtime` adapters both device residencies need; `tensorneat` 0.2.0 (editable `evoxc` branch, not declared); `tensordict` (via `dev`) for `go2_env.py`; `rsl-rl-lib>=5.0.0` (separate, PPO path only).
- `jax-rocm7-pjrt` 0.10.2 (PJRT C-API plugin, not declared) makes `xla` usable on ROCm; CUDA has no `xla` plugin, so `tell()` uses IREE there, and `tvm` needs `jaxlib` (absent in both environments).
- `torch` is no longer needed by this stack's GPU path: the torch-free loop runs without it, and it remains a Genesis dependency for the torch-present modes (`residency="numpy"`, `residency="device"` without `--torch-free`, the viewer, the PPO stack).
- The system ROCm HSA runtime (`/opt/rocm/lib/libhsa-runtime64.so.1.*`, 1.18.70100 with ROCm 7.1.0) is what long ROCm GPU rollouts need; torch 2.13.0+rocm7.1 bundles a 1.18.70101 one that corrupts AQL packets on this host — an environment fact, and `gs.init` selects the system runtime itself.

## Blocking APIs
Each item is a minimal reproducer plus the workaround this directory uses; none is fixed here.
1. `./genesis`: `RigidSolver._set_dofs_info` passes `envs_idx=None` to `kernel_set_dofs_kp`/`kernel_set_dofs_kv` when `batch_dofs_info=False`, which the torch-free kernel rejects with `QuadrantsRuntimeTypeError: Invalid type for argument envs_idx, got None`. Reproducer: build a multi-env rigid scene without torch with the default `RigidOptions` and let `scene.build()` write the PD gains. Workaround: `RigidOptions(batch_dofs_info=not HAS_TORCH)`.
2. `./genesis`: `gs.init(..., performance_mode=True)` fails torch-free during `scene.build()` (`owned_copy` → `kernel_copy_values` type error). Reproducer: `gs.init(backend=gs.gpu, performance_mode=True)` in a torch-free process, then build the Go2 scene. Workaround: `--torch-free` forces `performance_mode=False`.
3. `./genesis`: `Scene.get_error_envs_mask()` returns a `torch.bool` tensor with torch but an int32 `DeviceView` without it. Reproducer: print `scene.get_error_envs_mask().dtype` in both modes. Workaround: the state graph's `mask_is_bool`.
4. `./genesis`: the torch-free staged `set_qpos` requires the whole `(n_envs, n_values)` tile and applies `envs_idx` itself, while the torch path scatters only the rows it is given. Workaround: `_reset_rows`; a caller cannot tell the two contracts from the API.
5. `evoxc`: `iree.runtime.DeviceArray.reshape` (and any numpy function on a `DeviceArray`) goes through numpy dispatch and returns a HOST copy, so wrapping it in `IreeDevicePayload` later fails with `AttributeError: 'numpy.ndarray' object has no attribute 'to_host'`. Reproducer: build any single-output graph on `iree@rocm:0`, then `type(out.data.device_array.reshape((2,3)))` is `numpy.ndarray`. Workaround: a compiled `evoxc.reshape` graph (`build_episode_returns`).
6. `./tests` (report only): both device modules need `IGNORE_SCRIPT_PATTERNS` entries in `tests/test_examples.py`, and the shared venv has no `pytest`, so the three Go2 test modules could not run on this host.
7. Environment: a torch-free process must resolve `genesis` to this tree (the torch-optional `genesis/`); a `PYTHONPATH` pointing at another checkout picks up a torch-hard-importing `genesis` and dies with `ImportError`.

## Gotchas
- Pass a POSITIVE `axis` to `evoxc.concatenate`: evoxc copies a negative axis verbatim into StableHLO and `iree-compile` rejects it; `evoxc.stack(..., axis=-1)` is safe.
- `iree.runtime.DeviceArray.reshape` and every numpy function on a device array return a host copy, so a device buffer's shape is only changed by a graph — hence the `episode_returns` executable.
- `evoxc.constant` only works inside a trace, and a static matrix must be a runtime operand because `evoxc.matmul` rejects a static ndarray; the `(12,12)` matrices and the default-pose tile therefore travel as inputs and are re-staged per call (`evoxc.zeros` is a concrete creator, not a graph op).
- The control graph runs at the END of the step: writing its targets on the following iteration reproduces `simulate_action_latency`, and step 0 executes the default pose.
- Under pytest (`PYTEST_VERSION`) `try1.py` creates no viewer and runs 5 steps, mirroring the shortened `go2_backflip.py` playback; `--headless` (250 steps) and `--max-steps N` win over that cap, and `scene.viewer` is `None` whenever the viewer is not shown.
- The gait `step` input must be a 0-d `int32` ndarray; `np.ascontiguousarray` promotes 0-d to shape `(1,)` and the executable rejects it.
- `scene.clear_errno()` must be called for every row the graphs report in `error_mask` (and once per generation reset): a latched solver error otherwise re-raises `GenesisException: Invalid constraint forces causing 'nan'` on the next `scene.step()` although the graph already marked those rows dead.
- `qd.sync()` is the only fence between Quadrants and IREE: the DLPack import adds none and IREE's queue is not Quadrants' stream, so the rollout syncs after every `scene.step()` and after a reset write; a strided `DeviceView` slice is compacted with `.contiguous()` on the device first, because a DLPack export must be compact.
- `tilted` dominates `end_reasons` for untrained policies at the full horizon, and `--stop-when-done` (the default) truncates a full-horizon run as soon as every row has tilted, so quote throughput from `--no-stop-when-done` runs.
- `run_advance` takes `base_quat` already relative to the init pose (identity for the Go2 config, whose `base_init_quat` is `[1,0,0,0]`; backflip uses `[0,0,0,1]` and starts inverted) and world-frame `get_vel()`/`get_ang()`; the timeout fires when `episode_length + 1 > max_episode_length`, the dying step's reward is counted exactly once, `alive` never re-arms, and `episode_length` restarts at 0 on that step.
- Roll/pitch termination is `|sinp| > tanθ·cosp` and `|sinrcosp| > tanθ·cosrcosp` with the `cosrcosp·cosp <= 0` quadrant guard; do not add a second `cosp` factor (it shrinks the roll threshold with pitch and fires false positives).
- A mixed IREE-rollout + XLA-`tell()` process must re-select the executable's own backend before staging: `evoxc.backends.get(name)` sets a per-device-kind "preferred transfer backend" (last lookup wins), so `_stage` calls it first or IREE operands are staged by the XLA provider and fail with "the xla adapter requires a PJRT C API plugin".
- On ROCm the XLA client reserves a 143.77 GiB BFC pool plus up to 51.5 GB of Collective allocator at creation, so it needs an otherwise idle GPU, and it can abort during interpreter teardown, which is why a device-resident XLA `tell()` run ends with `os._exit(0)`. Note it also warns `TF_XLA_HSACO_CACHE_DIR is not set`, so kernels are recompiled in memory on every start.
- On ROCm the tell graph never finishes `iree-compile` (the process stays `R` indefinitely), so never wait on `--tell-backend iree` there.
- Any Genesis GPU run, `Go2NeatEnv`/`try1.py` included, gets the HSA repair from `gs.init`; a process that skips `gs.init` or sets `GS_HSA_REEXEC=0` keeps torch's bundled runtime and aborts a long rollout with `HSA_STATUS_ERROR_INVALID_PACKET_FORMAT` after ~50-600 steps, so it must set `LD_PRELOAD=<system libhsa-runtime64.so.1.*>` itself — only that library, never `libamdhip64` as well.
- `--residency device` never calls `Go2NeatEnv.executables()`; it receives the seven executables and reads the solver buffers directly, and any future residency must keep that rule or the cache counters stop matching the numpy path.

## Test Strategy
- `tests/test_examples.py` smoke-tests `try1.py` as a subprocess (no viewer, 5 steps under `PYTEST_VERSION`, skipped without `evoxc` via `EXAMPLE_DEPENDENCIES`); it ignores `*_train.py`, `*_eval.py`, `*_env.py`, `behavior_cloning.py`, `quadcopter_controller.py`, so `go2_neat_train.py`/`go2_neat_env.py` are documentation, not smoke tests, and `go2_backflip.py` is the other smoke test here.
- `go2_evox_kernels.py`, `go2_legacy_reference.py`, `go2_neat_kernels.py`, `go2_device_kernels.py` and `go2_device_rollout.py` are shared helper modules and must be in that harness's `IGNORE_SCRIPT_PATTERNS`; the two device modules are not matched by the `*_train.py`/`*_env.py`/`*_eval.py` patterns, so the harness would try to execute them.
